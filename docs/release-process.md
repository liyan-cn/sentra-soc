# 发布与供应链检查

持续集成在 Windows、Linux 和 Python 3.11–3.13 上执行编译与测试。安全工作流在主分支、
合并请求和每周计划任务中运行依赖漏洞审计与 Bandit 静态检查，并生成 CycloneDX JSON SBOM。

推送 `v*` 标签会构建 wheel 和源码包，使用 Twine 检查包元数据，并为制品生成
`SHA256SUMS`。工作流只上传 GitHub Actions 制品，不会自动发布到 PyPI，也不会自动创建
GitHub Release，避免未经维护者确认的外部发布。

发布工作流使用当前提交时间设置 `SOURCE_DATE_EPOCH`，使同一提交、相同构建环境生成的归档
时间戳稳定。不同源码提交或不同工具链版本仍应视为不同制品并重新签名、校验。

建议发布顺序：

1. 运行完整测试、`monitor3 doctor` 和日志样本回放。
2. 在临时目录安装构建出的 wheel，确认资源、迁移和命令入口。
3. 检查依赖审计、静态分析和 SBOM。
4. 更新版本号与 `CHANGELOG.md`，创建签名标签。
5. 下载 CI 制品并核对 SHA-256 后，再由维护者执行正式发布。

SBOM 是发布时依赖状态的快照，不代替持续漏洞监控。发现漏洞时应按 `SECURITY.md` 私下报告并协调修复。

## 目标服务器验收

部署完成后运行：

```bash
monitor3 release-check --require-backup
```

该命令检查配置与规则、SQLite 完整性和外键、WAL 模式、数据库迁移版本、磁盘余量、wheel
内置资源、配置要求的 Worker 心跳，以及最近自动备份的完整性和时效。`--json` 可供部署流水线
读取；任何必需项失败时进程返回非零状态。首次部署尚未启用备份前可省略 `--require-backup`，
正式切流前必须创建并演练至少一个备份。
